# 硬件后端接口

本次抽取保持现有 CPU/MPP 行为、公开参数、能力响应和持久化格式不变。
NVENC/QSV、设备选择和新的能力 API 属于后续功能，不在当前实现中。

## 调用路径

```text
detect_capabilities → 统一采集 FFmpeg 清单和设备节点 → registry.probe
                   → 各后端解释能力 → legacy_snapshot

decide_parameters → 公共尺寸/码率策略 → backend.plan_video
                  → 公共音轨/字幕校验 → 现有 effective/reasons

build_ffmpeg_argv → restore_video_plan → backend.build_video_args
                 → 公共输入输出、流映射、音频字幕和容器参数拼接

scheduler → registry.mode_chain / registry.label → 执行、取消和记录尝试
```

`media.py` 保留原有函数以及 `CapabilitySnapshot`、`MediaError` 导入路径。
已保存的 `effective` 可以独立还原 `VideoPlan`；构建命令不重新探测或决策。

## 后端契约

`ffpanel/hardware/types.py` 定义 `HardwareBackend` Protocol 和 dataclass：

- `id`：后端唯一标识；`device_paths`：需要由公共检测器查询的设备节点。
- `probe(inventory)`：同步解释已采集的编码器、解码器、滤镜和节点信息，返回
  `BackendCapabilities`。后端自行筛选清单，并用 `features` 表达其功能标记。
- `profiles()`：返回方案标识、名称、所属后端、解码方式以及下一个降级方案。
- `plan_video(request, profile, capabilities)`：校验并生成 `VideoPlan`，能力不足时
  抛出带错误代码的 `MediaError`，不在后端内降级。
- `build_video_args(plan)`：返回 `VideoArguments.before_input/after_input` 两个元组。
  输入前参数位于 `-i` 前，输入后视频参数位于流映射之后、音频字幕参数之前。

`VideoSettings` 承载公共层已确定的尺寸、旋转、SAR、变换需求、码率和帧率。
`VideoRequest` 额外携带源编码和目标编码；`VideoPlan` 记录方案、编码器及滤镜选择。
软件滤镜与现有码率参数由 `common.py` 的无状态函数复用。

后端不接收文件路径、任务或数据库对象，不启动进程，不处理缓存、上传、取消或恢复。
参数必须返回独立 argv 元素，不能返回 shell 命令字符串；后端不生成输入输出路径、
流映射、进度、音频字幕或容器参数。

## 注册和兼容边界

生产注册表在 `hardware/__init__.py` 显式注册 CPU、Rockchip，无动态发现。
注册时拒绝重复后端/方案、所属后端不符、缺失降级目标和降级环。

现有顺序为 `mpp_mpp → cpu_mpp → cpu_cpu`，关闭自动降级只尝试请求方案。
调度器不提前剔除能力不足的方案，继续记录每次失败、清理输出、重置进度并尝试下一项。
本次保留原有异常重试规则，包括未分类的 FFmpeg 失败；没有新增错误分类策略。

`compat.py` 是旧格式的唯一适配边界。旧快照的 MPP/RGA 布尔值是权威值，不能因为
mock 或历史快照没有设备节点而重新判定不可用。真实探测仍保留 MPP 对编码器、
解码器和节点的联合要求。公共检测器仍执行原有四条 FFmpeg 命令及 rclone 可用性检查。

后续新增后端时：实现 Protocol，添加注册项，并提供独立能力与参数测试。
后端可定义自己的方案标识和特性，通用注册表不依赖旧 HardwareMode 枚举。
要让新方案可被真实任务选择，还需另行扩展公开 schema、前端、能力快照适配和部署；
当前旧快照不表达多设备状态，不应在此适配器中推断 GPU 选择。

## 验证

`tests/test_hardware_compat.py` 在抽取前建立 72 组基线，比较完整决策及 argv 顺序，
覆盖三种模式、两种编码、两种码率策略和无变换/缩放/SAR/三个旋转方向。
`tests/test_hardware.py` 覆盖能力缺失、旧快照、注册错误和测试后端的公共命令拼接。
调度器降级、取消、重试与恢复沿用现有集成测试。

运行 `pytest`、`ruff check .`、`mypy ffpanel`。Windows 临时目录权限受限时可指定
`pytest --basetemp=.pytest-tmp/<本次运行的唯一目录>`。这些测试不要求真实 GPU；
发布前的 RK3588 实机验证须单独记录。
